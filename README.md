# 07 - 프로그램 구조 실습

7주차 강의자료의 실습 1~5, 6-1, 6-2를 구현했다.
각 소스의 주석에 예상 결과와 이유를 적었다.

| 실습 | 파일 | 확인한 결과 | 이유 |
| --- | --- | --- | --- |
| 1 수정 전 | `test01-before/main.c` | `y` undeclared 컴파일 오류 | `y`의 범위가 while 블록 안으로 제한됨 |
| 1 수정 후 | `test01.c` | `y = 4` | `y`를 main의 블록으로 옮겨 while 이후에도 사용 가능 |

실습 3의 강의자료에는 i의 초기값이 빠져 있어 `int i = 10;`으로 보완했다.
`inc(i);`를 `i = inc(i);`로 바꾸면 반환값이 저장되어 호출 후 i는 11이 된다.

## VS Code 실행

1. 이 `07` 폴더를 VS Code의 폴더 열기로 연다.
2. 실행할 C 파일을 열고 F5를 누른다.
3. 실행 결과는 VS Code 내장 터미널에 남는다.

`test06-1`에서는 main.c와 sub.c 중 어느 파일을 열어도 두 파일을 함께 빌드한다.
실행 파일은 `test06-1/main.exe`이다.

`test01-before/main.c`와 `test06-2`는 오류를 관찰하기 위한 코드다.
이 파일들은 빌드 실패가 예상 결과이며 실행 파일이 생성되지 않는다.
오류 실습에서 F5가 실패하면 이전 실행 파일로 계속 실행하지 말고 빌드를 중단한다.

디버깅할 때는 빌드에 성공한 실행 파일을 임시 폴더의 `07-debug.exe`로 복사한다.
한글 경로 때문에 GDB가 실패하지 않도록 디버그 경로도 매핑한다.

## Makefile

GNU make가 설치된 환경에서 저장소 루트를 기준으로 실행한다.

```sh
make
make scope-error
make linkage-error
```

`make`는 실습 1 수정 후, 2, 3, 4, 5, 6-1을 빌드한다.
`scope-error`와 `linkage-error`는 해당 오류를 재현하고 실패 상태로 종료하는 별도 대상이다.
이 컴퓨터에는 make가 없어 검증은 VS Code와 동일한 `scripts/build.ps1` 및 GCC로 진행했다.

## 검증

- 정상 실습 6개를 C17, `-Wall -Wextra` 옵션으로 컴파일하고 전체 출력을 비교했다.
- 수정 전 실습 1의 컴파일 오류와 실습 6-2의 링크 오류를 각각 확인했다.
- 실습 6-1은 GDB의 main 중단점에서 정지한 뒤 10을 출력하고 정상 종료했다.
